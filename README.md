# sstryujin.pro — деплой-репозиторий

Это **только собранная статика**, не исходный код. Правки сюда не вносятся напрямую — весь контент/дизайн/логика живёт в исходном репозитории и сюда только копируется.

- **Исходники:** `~/Documents/Проекты/feniks-site` (Next.js, TypeScript, Tailwind, Framer Motion), локальный репозиторий, не на GitHub — полная структура, правило анонимизации текущего работодателя и история решений в его `README.md`.
- **Этот репозиторий:** `github.com/sstruyjin/sstruyjin-pro`, ветка `main`, корень репозитория.

## Деплой

GitHub Pages. Кастомный домен — файл `CNAME` (`sstryujin.pro`). DNS — панель hoster.by, A-записи на IP GitHub Pages, `www` → `sstruyjin.github.io`. `.nojekyll` обязателен — без него GitHub Pages ломает папку `_next/`.

Пуш в `main` обновляет сайт за 1-2 минуты.

## Как обновить

```bash
cd ~/Documents/Проекты/feniks-site
npm test && npm run lint && npm run build
rm -rf ~/Documents/Codex/sstruyjin-pro/_next   # иначе чанки прошлых сборок копятся вечно
cp -r out/. ~/Documents/Codex/sstruyjin-pro/
cd ~/Documents/Codex/sstruyjin-pro
git add -A && git commit -m "..." && git push origin main
```

Не редактировать `index.html` или любой другой файл здесь вручную — следующий деплой из `feniks-site` всё равно перезапишет правки, и источник правды разъедется.

`_next/static/` содержит хэшированные по контенту файлы — каждая сборка создаёт новые имена, а старые становятся мусором. Поэтому `rm -rf _next` перед копированием — обязательный шаг, не опция.
