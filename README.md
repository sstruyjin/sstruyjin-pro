# sstryujin.pro — личный сайт Владимира

Статический сайт-визитка, одна страница. Без сборки, без бэкенда — редактируется `index.html` напрямую, чистый HTML/CSS, шрифты Google Fonts по ссылке.

## Деплой

GitHub Pages, ветка `main`, корень репозитория. Кастомный домен — через файл `CNAME` (`sstryujin.pro`, не путать с `sstruyjin` — это GitHub-логин Владимира, домен пишется иначе). DNS домена — в панели hoster.by, A-записи указывают на IP GitHub Pages, `www` — CNAME на `sstruyjin.github.io`.

Любой пуш в `main` обновляет сайт за 1-2 минуты.

## Контент и позиционирование

Источник правды по содержанию (кейсы, формулировки, что можно/нельзя заявлять) — Obsidian-вейлт Владимира, не этот репозиторий:
- `~/Documents/Сферы/Личное/Феникс — бренд и продукт (план)/06_PITCH_AND_RESUME_DRAFT.md` — актуальный текст позиционирования и статус кейсов.
- `~/Documents/Сферы/Личное/Профиль — Карьера и кейсы.md` — доказательная карта карьеры, откуда берутся кейсы.
- `~/Documents/Сферы/Личное/Феникс — методы и шаблоны/14_Методология_доказательного_кейса.md` — методология, как оформлять новый кейс (7 полей, таблица утверждений, что нельзя переносить между статусами доказанности).

Перед тем как менять кейсы или формулировки на сайте — сверяться с этими файлами, не выдумывать цифры/результаты.

## Что уже решено (не пересматривать без причины)

- Формат: один статический HTML-файл, не React/сборка — аудитория узкая, приходит по личным рекомендациям, не нужна сложность.
- Продвижение: без SEO/таргета/контекста — аудитория не ищется по ключевым словам, канал — личные разговоры.
- Дизайн: японский минимализм (ма — пространство, тонкая линия, один акцент-печать), не карточки/блюпринт — решение от 2026-09-28.
- Кейсы без проверенных цифр публикуются только качественно, без конкретных чисел (см. методологию выше).
